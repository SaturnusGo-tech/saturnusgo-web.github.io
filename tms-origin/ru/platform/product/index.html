Управление тестами для QA‑команд и агентов

В Falcon команда ведёт тест-кейсы, проверяет API и планирует регрессию. Через MCP агенты работают с теми же тестами и результатами.

Репозиторий тест-кейсов

Один кейс можно включить в несколько наборов. Если в разных сценариях повторяется одна процедура, например вход в аккаунт, её достаточно описать один раз.

Общие шаги

Требования

В спецификации перечислены кейсы, которые её проверяют. Когда требования меняются, у команды уже есть список тестов для пересмотра.

Дефекты

Дефект связан с конкретной попыткой. Разработчику доступны шаги, результат и вложения из прогона.

Переезд из другой TMS

Falcon восстанавливает папки по путям в файле экспорта. До импорта видно, куда попадёт каждый кейс.

Проекты и портфели

Веб и мобильные приложения могут входить в один портфель. У каждого проекта при этом свой репозиторий, свои прогоны и метрики.

Руководство по портфелям

Пользовательские поля

Для мобильных кейсов «Платформа» может быть обязательным полем с двумя вариантами — iOS и Android.

Типы полей

Тестирование API

В коллекциях проекта хранятся запросы к сервисам, а в окружениях — адреса и переменные для разных стендов.

HTTP
Цепочки запросов с проверками статуса и тела ответа.
MCP
Схемы инструментов и вызовы с тестовыми аргументами.
gRPC
Методы сервиса из файла .proto или через gRPC reflection.
WebSocket
Отправка сообщений и просмотр входящих кадров.
Socket.IO
Именованные события и подписки на события сервера.
Data
Запросы к базе данных и просмотр результатов.
Kafka
Чтение и запись сообщений в топике, включая ключи и заголовки.

Наборы для регрессии

Команда собирает набор один раз и запускает его на новых сборках. У каждого прогона свои результаты и ответственные за проверки.
